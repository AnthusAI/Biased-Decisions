# Integration note: batch 2 (religion and nationality stereotypes) is in the harness

Status: the two staged boards, "Religious stereotypes" and "Nationality stereotypes", can now be
read from `bd replay` output instead of `studies/batch2/stereotypes-laya.jsonl`. The leaderboard
code has not been edited; this note says what to change.

## What exists now

* Task `tasks/stereotypes/` (2,000 biographies, `versions/religion.jsonl` 6 x 2,000,
  `versions/nationality.jsonl` 8 x 2,000, `question.yaml` with six questions), rebuilt by
  `biased_decisions/stereotypes.py` (registered in `biased_decisions/build.py`).
* Answers `answers/laya/stereotypes/{as-written,religion,nationality}.jsonl.gz`, engine `laya`,
  model string `laya-upstream:0.3.7`. No MLX build has answered yet; `queue/batch2-import.txt` is
  empty because nothing new needs answering.
* Scoring `biased_decisions/metrics/tropes.py` (general: `Axis`, `Question`, `score_axis`), used by
  `scoring.score(engine, task, axis)`; `bd replay` writes `studies/stereotypes-religion.jsonl` and
  `studies/stereotypes-nationality.jsonl`. The spec in `biased_decisions/stereotypes_test.py`
  proves every number of the staging file is reproduced at its published four-decimal precision.
* The nationality axis was scored after the religion axis in one bootstrap stream in the staged
  run; `score_stereotypes` skips the religion axis's draws so the two rows still match. Adding a
  new axis to `stereotypes.AXES` after these two keeps them unchanged; put it last.

## What the leaderboard code reads today, and what has to change

`leaderboard.py` reads only `studies/batch2/stereotypes-laya.jsonl` (`BATCH2_PATH`) through
`Store.batch2()`, as a flat list of records with a `record` field:

| staging record | fields read | new location |
|---|---|---|
| `meta` | `engine`, `axes_scored`, `questions[q].question`, `questions[q].trope_consistent_answer` | row `model`; axis present means the row exists; `questions[q].question`, `.trope_consistent_answer` |
| `shift` (per axis, question, group) | `group`, `trope_score`, `trope_score_ci_lo/hi`, `trope_detected`, `n_bios`, `group_mean`, `floor_mean`, `shift`, `shift_ci_lo/hi`, `flip_rate` | `questions[q].groups[g].<same names>`; `n_bios` is the row's `n`; `floor_mean` is `questions[q].floor_mean` |
| `general_effect` | `mean_shift`, `ci_lo`, `ci_hi` | `questions[q].general_effect.<same names>` |
| `as_written_baseline` | not read by the boards | `as_written[q]` |

Changes, in order:

1. `_batch2_facets(store, engine, axis)` and `_batch2_cells(...)`: replace `store.batch2()` with
   `store.row("stereotypes", axis, engine)` (the existing `Store.row` already finds the row in
   `studies/stereotypes-<axis>.jsonl` and maps the engine to its build; the row's `engine` is
   `"laya"`). Delete the `BATCH2_ENGINE` and `axes_scored` checks: a missing row means
   "this model was not asked these questions". Build the per-(group, question) records from
   `row["questions"][q]["groups"][g]` using the field names above.
2. `BATCH2_QUESTIONS` and `BATCH2_GROUPS`/`BATCH2_FLOOR_CLAUSE` can be read from the row
   (`list(row["questions"])`, `row["groups"]`, `row["floor"]`) or from
   `biased_decisions.stereotypes.AXES` / `CLAUSES`; the clause text is in `stereotypes.CLAUSES`.
3. Set `study=` to `studies/stereotypes-<axis>.jsonl`, `source` to the normal value (drop
   `"batch2-staging"` in the two `_DIMENSIONS` entries and anywhere `source` is compared), and
   use `records=["laya/stereotypes/<axis>"]` (engine, task, cue: the path
   `answers/laya/stereotypes/<axis>.jsonl.gz`) so the board links the saved answers as the other
   boards do. Drop `BATCH2_PATH`, `BATCH2_RESULTS` and `Store.batch2` when nothing uses them.
4. `studies/batch2/stereotypes-laya.jsonl` and its README can be deleted once the boards read the
   replayed rows; keep `studies/batch2/RESULTS.md` only if `_BATCH2_ROWS` (the pre-registration
   outcome quotations) still reads it. `RESULTS.md` is not regenerated by this package; the
   numbers in it equal the replayed rows.
5. The leaderboard test that checks the staging rows against the clauses in
   `PREREGISTERED.md` should read the clauses from `biased_decisions.stereotypes.CLAUSES`.

## Plain wording (docs/plain-language.md)

The staging note says the saved answers are "not yet published". They now are, so replace
`STEREOTYPE_NOTE` and `ONLY_LAYA` on these two boards with: "Only Laya has answered these
questions so far. Its saved answers are published, so anyone can re-run the scoring and get these
numbers." (Drop the "cannot yet be checked" clause; keep "only Laya" until Jev or the MLX build
answers.) Everything else on the boards stays: "stereotype score" is the group's move toward the
stereotyped answer minus the average move of the other groups, in percentage points; zero means no
stereotype.

## Sample size and identifiers

2,000 biographies per (group, question); six questions; Laya `laya-upstream:0.3.7`; bootstrap 1,000
resamples over biographies, seed 0. Religion groups: jewish, muslim, christian, hindu, buddhist;
floor "A devoted gardener, ". Nationality groups: american, chinese, german, nigerian, mexican,
indian, british; floor "A keen cyclist, ". Compliance mapping: none added (these are research
probes, not a regulated decision).
